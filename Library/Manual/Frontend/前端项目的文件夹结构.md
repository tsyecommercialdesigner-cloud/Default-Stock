# 源代码与公开资源

在常见的前端项目（React、Vue、Vite、Next.js 等）中：

| 文件夹       | 主要作用                        | 是否参与构建处理       |
| --------- | --------------------------- | -------------- |
| `src/`    | 放应用的源代码：页面、组件、样式、业务逻辑、接口调用等 | 会被打包工具编译、转换和打包 |
| `public/` | 放静态公开资源：图片、图标、字体、下载文件等      | 通常原样复制到构建产物根目录 |

例如一个 Vite 项目：

```text
my-app/
├── src/
│   ├── main.jsx        # 应用入口
│   ├── App.jsx         # 根组件
│   ├── components/     # 可复用组件
│   ├── pages/          # 页面
│   └── assets/         # 由代码引用的图片、样式等资源
├── public/
│   ├── favicon.ico
│   ├── robots.txt
│   └── logo.png
└── index.html
```

核心区别：

- `src/` 中的文件需要通过代码 `import` 进来，例如：

```js
import logo from "./assets/logo.png";
```

构建工具会处理这张图片，可能压缩、生成带哈希的文件名，并自动修正最终引用路径。

- `public/` 的文件不需要 `import`，通常通过网站根路径直接访问：

```jsx
<img src="/logo.png" alt="Logo" />
```

构建时它会被直接复制。例如 `public/logo.png` 最终通常是 `dist/logo.png`。

- 放在 `src/assets/` 的资源适合“组件或页面私有、由代码依赖管理”的文件。
- 放在 `public/` 的资源适合“必须固定 URL 访问、无需构建工具处理”的文件，例如 `favicon.ico`、`robots.txt`、网站验证文件、供用户下载的 PDF 或大体积媒体文件。

补充：不同框架规则略有差异。比如 Next.js 通常使用 `app/` 或 `pages/` 放源代码，但 `public/` 的含义基本一致。
