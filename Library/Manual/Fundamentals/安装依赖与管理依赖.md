## 验证安装命令

安裝完成後，可以執行以下指令確認安裝成功：

```bash
nvm --version       # 應顯示 nvm 版本
node --version      # 應顯示 Node.js 版本
npm --version       # 應顯示 npm 版本

```

如果所有指令都能正確顯示版本號，代表你的開發環境已經準備就緒！

# Node  專案管理：nvm
## Node.js 版本管理：nvm

**nvm**（**Node Version Manager**）是 Node.js 的版本管理工具，讓你可以同一台電腦上安裝和切換多個 Node.js 版本。

### nvm 安装
#### macOS/Linux 安裝

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
```

#### Windows 安裝

Windows 使用者請下載 nvm-windows 安裝程式。

### nvm 常用指令

```bash
nvm install 22       # 安裝 Node.js 22
nvm install --lts    # 安裝最新 LTS 版本
nvm use 22           # 切換到 Node.js 22
nvm list             # 列出已安裝的版本
```

---
## Node.js 套件管理：npm

**npm**（**Node Package Manager**）是 Node.js 的預設套件管理工具，安裝 Node.js 時會自動附帶。當你透過 nvm 安裝 Node.js 後，npm 就已經可以使用了。

### npm 常用指令

```bash
npm init -y          # 初始化專案（產生 package.json）
npm install lodash   # 安裝套件
npm install          # 安裝 package.json 中的所有相依套件
npm run dev          # 執行 scripts 中定義的 dev 指令
npm update           # 更新所有套件
```

# Python 專案管理：uv

## 為什麼選擇 uv？

| 特性              | pip + venv | Poetry   | uv          |
| --------------- | ---------- | -------- | ----------- |
| **速度**          | 慢          | 中等       | 極快（10-100x） |
| **Python 版本管理** | 需要 pyenv   | 需要 pyenv | 內建          |
| **Lock 檔案**     | 無          | 有        | 有           |
| **相容性**         | -          | 部分       | 完全相容        |
| **學習曲線**        | 低          | 中        | 低           |

uv 是 2025-2026 年 Python 開發者的首選工具，推荐用 `uv` 管理 Python 依赖。
**uv** 是由 Astral（Ruff 的開發者）推出的新一代 Python 專案管理工具，以 Rust 撰寫，速度比傳統的 pip 快 10-100 倍。它可以取代 pip、virtualenv、pyenv、poetry、pipenv 等多個工具，是目前 Python 生態系統中最推薦的專案管理方案。
## uv 安装

### macOS/Linux 安裝：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### Windows 安裝：

#### 方式一：PowerShell 安装（推荐）

注意：不要以直接双击 PowerShell 的方式打开，

而是：手动按 `Win + R`，输入`powershell`后敲回车，然后执行官方推荐命令：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

这个写法来自 uv 官方安装文档，比直接执行下面这个更稳：

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

安装完成后，系统提示设置环境变量，但不一定要手动执行，取决于你接下来怎么用终端。

推荐方式：关闭终端，重新打开。

如果你不想重开终端，

当前在 PowerShell，就执行：

```powershell
$env:Path = "C:\Users\Administrator\.local\bin;$env:Path"
```

当前在 cmd，就执行：

```shell
set Path=C:\Users\Administrator\.local\bin;%Path%
```

当前在 Git Bash 里，就执行：

```shell
export PATH="/c/Users/Administrator/.local/bin:$PATH"
```

目的只是为了让 PATH 生效，最省事的做法还是重开终端。

如果你想重开终端：

关闭当前 Git Bash，重新打开一个新的 Git Bash，然后验证：

```bash
uv --version
```

能看到版本号就表示安装成功了。

#### 方式二：如果你已经装了 Scoop

```shell
scoop install uv
```

然后重新打开终端：

```shell
uv --version
```

#### 方式三：如果你已经装了 Python/pip

```shell
pip install uv
```

然后：

```shell
uv --version
```

不过 Windows 上我更推荐第一种，最省心。

另外，如果你装完后 PowerShell 能识别 `uv`，但 Git Bash 还是提示找不到，通常是 PATH 没刷新。关闭 Git Bash 重新打开即可；不行就重启一下终端或电脑。

## uv 使用指南

### uv 常用指令總覽

```shell
# 專案管理
uv init              # 初始化新專案
uv sync              # 同步依賴
uv add <package>     # 新增套件
uv remove <package>  # 移除套件
uv lock              # 更新 lock 檔

# Python 版本管理
uv python install 3.12   # 安裝 Python 3.12
uv python list           # 列出已安裝版本
uv python pin 3.12       # 固定專案 Python 版本

# 執行
uv run <command>     # 在虛擬環境中執行
uvx <tool>           # 執行一次性工具（不需安裝）

# 相容模式（取代 pip）
uv pip install <package> # 安裝套件
uv pip freeze        # 列出已安裝套件
uv venv              # 建立虛擬環境
```

### 建立新專案：uv init

使用 `uv init` 可以快速建立一個標準的 Python 專案結構：

```bash
# 建立新專案
uv init my-project
cd my-project

# 或在現有目錄初始化
mkdir my-project && cd my-project
uv init
```

執行後會產生以下檔案結構：

```text
my-project/
├── .python-version    # 指定 Python 版本
├── main.py            # 主程式進入點
├── pyproject.toml     # 專案設定檔（核心）
└── README.md          # 專案說明
```

如果你需要建立可發布的套件結構，可以使用 `--lib` 選項：

```bash
uv init --lib my-library
```

這會產生包含 `src/` 目錄的套件結構：

```text
my-library/
├── .python-version
├── pyproject.toml
├── README.md
└── src/
    └── my_library/
        └── __init__.py
```

### pyproject.toml：專案設定檔

`pyproject.toml` 是現代 Python 專案的核心設定檔，uv 會自動產生並管理：

```toml
[project]
name = "my-project"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```

你可以在 `dependencies` 中加入套件依賴：

```toml
dependencies = [
    "flask>=3.0.0",
    "requests>=2.31.0",
    "pandas>=2.0.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=8.0.0",
    "ruff>=0.1.0",
]
```

### 安裝依賴：uv sync

`uv sync` 是 uv 最強大的指令，它會：

1. 讀取 `pyproject.toml` 中的依賴
2. 自動建立虛擬環境（如果不存在）
3. 安裝所有依賴套件
4. 產生或更新 `uv.lock` 鎖定檔

```bash
# 同步所有依賴
uv sync

# 包含開發依賴
uv sync --dev

# 包含特定的 optional dependencies
uv sync --extra dev
```

### uv.lock：依賴鎖定檔

`uv.lock` 是自動產生的鎖定檔，記錄所有依賴的精確版本：

```toml
version = 1
requires-python = ">=3.12"

[[package]]
name = "flask"
version = "3.0.2"
source = { registry = "https://pypi.org/simple" }
dependencies = [
    { name = "werkzeug" },
    { name = "jinja2" },
    ...
]
```

#### 為什麼 uv.lock 很重要？

* 確保團隊成員安裝完全相同的套件版本
* 專案可以在不同電腦上完美重現
* 避免「在我電腦上可以跑」的問題

### 新增與移除套件

```bash
# 新增套件（會自動更新 pyproject.toml 和 uv.lock）
uv add flask
uv add "pandas>=2.0.0"

# 新增開發依賴
uv add --dev pytest ruff

# 移除套件
uv remove flask
```

### 執行專案

```bash
# 執行 Python 腳本（自動使用虛擬環境）
uv run python app.py

# 執行模組
uv run python -m my_project

# 執行專案定義的腳本
uv run my-script
```

### 專案移轉：一鍵重現環境

當你把專案分享給其他人，或在新電腦上開發時，只需要：

```bash
# 複製專案
git clone https://github.com/user/my-project.git
cd my-project

# 一鍵安裝所有依賴（根據 uv.lock）
uv sync
```

這就是 uv 的強大之處：**pyproject.toml + uv.lock = 完美可重現的專案環境**

# GitHub CLI：gh

**gh** 是 GitHub 官方的命令行工具，讓你可以在終端機中直接操作 GitHub 的各項功能，包括 Pull Request、Issue、Repository 等。Agent 會使用 gh 來幫你處理 Git 相關的任務。

## gh 安装
### macOS 安裝

```bash
brew install gh
```

### Windows 安裝

```bash
winget install --id GitHub.cli
```

### Linux（Debian/Ubuntu）安裝

```bash
sudo apt install gh
```

## 首次登录

```bash
gh auth login
```

按照提示選擇 GitHub.com，然後透過瀏覽器完成授權。

## gh 常用指令

```bash
gh repo clone owner/repo    # 複製儲存庫
gh pr create                # 建立 Pull Request
gh pr list                  # 列出 Pull Request
gh issue create             # 建立 Issue
gh issue list               # 列出 Issue
gh repo view --web          # 在瀏覽器開啟儲存庫
```
